# Tab Sleep · 标签页休眠

[English](README.en.md) ｜ 中文（当前）

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Manifest V3](https://img.shields.io/badge/Manifest-V3-informational.svg)](src/manifest.json)

> **重启浏览器时，上百个标签页一起加载、内存瞬间冲到十几 GB、机器卡死好几分钟**
> ——这是本扩展主要解决的问题。
>
> 次要地，它也能在你内存告急时一键把不用的标签页「休眠」起来。

基于 Chrome 原生 `chrome.tabs.discard()`：**不关闭标签页、不替换成假页面**，
休眠后点击标签页即可自动重新加载。

```bash
# 30 秒上手：克隆 → 加载 src/ → 完事（无构建步骤）
git clone <repo> && cd tab-sleep
# chrome://extensions/ → 开发者模式 → 加载已解压的扩展程序 → 选择 src/
```

---

## 它解决什么问题

浏览器给每个标签页分配独立的渲染进程。标签页一多，后台进程就开始吃内存。
但真正让人崩溃的是**重启**：会话恢复会把上次的上百个标签页**同时**加载，
内存在几十秒内冲到 15–20 GB，磁盘疯狂读盘，接下来几分钟基本没法用。

**启动抢先休眠**（默认开启）针对的正是这一刻：浏览器恢复的标签页保持未加载状态，
标签页的标题、图标、位置都在，**点哪个才加载哪个**。重启 200 个标签页的代价，
约等于只加载当前这一个。

配合日常使用，它还能：

- **内存告急时一键减负**：休眠当前页，或除当前页之外全部休眠，可中途取消。
- **免打理**：按空闲时长自动休眠；固定标签页、正在播放声音的标签页、
  白名单域名默认不休眠，重要页面不会被误伤。
- **唤醒后回到原位**：可选恢复滚动位置与表单内容（密码字段从不采集）。

## 项目目标

| 目标                               | 说明                                     |
| ---------------------------------- | ---------------------------------------- |
| 不关闭标签页也能释放内存           | 原生 discard，标签页本身保留             |
| **重启后恢复的标签页不要一起加载** | 本项目最核心、工程量最大的能力           |
| 好页面不被误伤                     | 白名单 + 单页锁定 + 固定/发声/内部页排除 |
| 唤醒后回到原来的样子               | 滚动位置与表单内容恢复                   |
| 用户不需要惦记它                   | 自动休眠与默认合理的排除规则             |

### 非目标

我们**不**做这些，它们是设计边界而不是待办事项：

- 不做标签页管理器：没有会话保存/恢复、标签页分组、垂直标签栏。
- **不做占位页**：休眠后绝不把页面替换成自定义 DOM——那会破坏站点的真实行为，
  同类扩展的历史事故都源于此（[ADR-0001](docs/adr/0001-native-discard-over-placeholder.md)）。
- 不保留页面内 JS 状态：`discard()` 会销毁渲染进程，游戏进度、复杂 SPA 状态必然丢失。
- 不支持 Firefox / Safari：只做 Chromium 内核。
- 不引入构建步骤：`src/` 就是产物，克隆下来就能改。

## 应用场景

1. **调研 / 开发时开几十上百个标签页**
   看完一批，点「休眠其他页」，只留当前页，内存立刻降下来。
2. **每天重启浏览器，会话里有几百个标签页**
   开着启动抢先休眠，重启的代价约等于加载一页；点开哪个才加载哪个。
3. **笔记本 / 老机器续命**
   配合自动休眠，后台标签页不再持续占用内存与 CPU。

## 与同类扩展的差异

|                              | 本扩展                        | 典型的标签页休眠扩展    | 浏览器内置的「内存节省程序」 |
| ---------------------------- | ----------------------------- | ----------------------- | ---------------------------- |
| 休眠方式                     | 原生 `discard()`              | 部分使用占位页替换 DOM  | 原生 `discard()`             |
| **重启时不加载恢复的标签页** | ✅ 三层机制，扩展加载即生效   | ⚠️ 依赖浏览器自己的策略 | ⚠️ 由浏览器判断，时机不可控  |
| 域名白名单 / 单页锁定        | ✅ 两者都有，且批量休眠也遵守 | 通常有                  | 白名单较粗                   |
| 唤醒后恢复滚动位置与表单     | ✅ 密码字段从不采集           | 通常不恢复              | ❌                           |
| 需要联网 / 收集数据          | ❌ 不联网、不收集             | 视实现而定              | ❌                           |

浏览器内置功能是**必要但不够**：它在后台慢慢丢弃标签页，但浏览器启动的那一刻
它是关着的，恢复出来的标签页会一起加载。本扩展的启动抢先休眠补的就是这个缺口。

## 快速上手

### 安装（约 1 分钟）

1. 打开 `chrome://extensions/`，打开右上角「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本仓库的 **`src`** 目录（不是仓库根目录）。
3. 工具栏出现扩展图标即安装成功。适用于 Chrome / Edge 等 Chromium 内核浏览器。

### 基本使用

- 点工具栏图标打开弹窗：**休眠其他页**（可中途点同一按钮取消）、按单个标签页
  休眠 / 唤醒 / 加锁。
- 右键菜单：休眠本页、休眠其他页、把当前域名加入/移出白名单。
- 唤醒：**直接点击休眠的标签页**即可。
- 快捷键：`Alt+S` 休眠当前页，`Alt+Shift+S` 休眠其他页
  （可在 `chrome://extensions/shortcuts` 里改）。

## 设置速览

在弹窗点「设置」进入选项页（或右键扩展图标 → 选项）：

| 设置                                               | 默认值                         |
| -------------------------------------------------- | ------------------------------ |
| 固定标签页不休眠 / 发声标签页不休眠 / 图标角标计数 | 开                             |
| 休眠其他页之前先确认                               | 开                             |
| 启动抢先休眠（恢复的标签页保持未加载）             | 开；固定标签页默认不含在内     |
| 自动休眠                                           | 关；开启后默认空闲 30 分钟休眠 |
| 恢复滚动位置 / 恢复表单内容（密码除外）            | 开                             |

白名单默认已包含 Gmail、Slack、Notion、Figma、Zoom 等常用协作站点，可在选项页
自行增删，支持 `*.example.com` 这类通配写法。

## 原理与局限

**一句话原理**：调用 Chrome 原生 `chrome.tabs.discard()` 卸载页面内容，标签页本身保留，
标题和图标都在，点击即重载。可用 Chrome 任务管理器（`Shift+Esc`）对比验证内存变化。

**启动抢先休眠**用三层机制兜底——在标签页创建的那一瞬间拦截、监听加载事件兜底、
启动后 45 秒内周期性清扫；且窗口只由浏览器真正启动的信号打开，
**扩展更新绝不会误触发**。完整机制见
[架构文档](docs/ARCHITECTURE.md#64-启动抢先休眠核心能力)。

**局限**：

- 页面内的 JS 运行状态（游戏进度、复杂单页应用状态）不会保留；
- 复杂富文本编辑器的内容可能无法完整恢复；
- `chrome://` 这类浏览器内部页面无法休眠；
- 启动后约 45 秒窗口内新开的后台标签页也会被抢先休眠（点击即加载，体验一致）。

完整验收步骤（含 200 标签页真机对照）见
[docs/STARTUP-SUSPEND-TEST.md](docs/STARTUP-SUSPEND-TEST.md)。

## 隐私

- **不收集任何用户数据，不向任何服务器回传数据，没有任何分析或遥测。**
- 所有设置与状态只存在本地 `chrome.storage.local` / `session`；
  休眠标签页的滚动位置与表单内容在被唤醒时读取一次后**立即删除**，密码字段从不采集。
- 唯一的对外请求是加载页面自己声明的图标（与浏览器自身行为一致），
  且只在打开弹窗时发生；我们计划用 Chrome 内置的 `favicon` 权限把它也去掉
  （[路线图 N1](docs/ROADMAP.md)）。
- 为什么需要「读取所有网站」权限：休眠/唤醒要在本地捕获滚动位置与表单内容，
  数据不出本机。完整说明见 [PRIVACY.md](PRIVACY.md)。
