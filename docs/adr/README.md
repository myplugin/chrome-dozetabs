# 架构决策记录 / ADR

这里记录**为什么**这个项目是现在这个样子。代码能告诉你"做了什么"，
ADR 告诉你"为什么不选另一条路"——以及在什么条件下应该重新考虑。

## 什么时候需要写 ADR

- 引入或移除一个浏览器权限
- 改变数据存储位置或结构
- 引入依赖、构建步骤或新的运行环境
- 在两个都能工作的方案之间做了取舍，且未来可能有人想推翻它
- 修掉一个 bug 时发现根因是某条设计约束被违反

**不需要** ADR：重命名、修错别字、加一个设置项、纯文案调整。

## 约定

- 文件名：`NNNN-短横线小写标题.md`，编号不复用。
- 状态：`已采纳` / `已废弃（被 NNNN 取代）` / `提议中`。
- 已被取代的 ADR **不删除**，在头部标注取代关系。
